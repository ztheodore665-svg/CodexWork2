# 单路口案例集（赛题功能一"典型路口"交付件）

> 位置：**项目主目录 `intersection_cases/`**（醒目可见，属于可交付件）。

本目录为**四个典型路口**的独立 SUMO 工程，每个目录均可单独运行（自带车流与信号程序），
也已被平台自动扫描，可在网页顶部路网下拉中直接选择加载演示。

## 目录结构

```
intersection_cases/
├── demo_1/   案例路口1 · 十字+多转向（6 相位，含转向流量）
├── demo_2/   案例路口2 · T 形路口（4 相位）
├── demo_3/   案例路口3 · 十字路口（4 相位）
├── demo_4/   案例路口4 · 十字路口（4 相位）
└── README_单路口案例说明.md
```

每个 demo 工程内含：
- `demo_N.net.xml` 路网（单信号控制路口，phase 程序内嵌）
- `demo_N.flow.xml` 各进口流量（3600s 均匀流）
- `demo_N.turn.xml` 转向比例（路口 OD 需求）
- `demo_N.rou.xml` 已生成路由车流（jtrrouter）
- `demo_N.sumocfg` 工程配置（SUMO GUI 双击可直接打开）
- `algorithm.py` **已填写的调度算法**：Webster 最优配时执行器
  （切相位时把程序时长改写为该路口最优配时；黄灯保留；运行：`python algorithm.py [步数]`）

## 最优调度方案

针对各路口流量用 **Webster 最优配时**（平台方案一核心算法）重算并仿真验证：

| 路口 | 原配时周期 | 原平均等待 | 最优配时周期 | 优化后等待 | 降幅 |
| --- | --- | --- | --- | --- | --- |
| demo_1 | 104s | 217.9s | 39s | 36.0s | 83% |
| demo_2 | 96s | 50.8s | 38s | 7.9s | 84% |
| demo_3 | 108s | 118.0s | 38s | 27.3s | 77% |
| demo_4 | 107s | 109.6s | 38s | 27.3s | 75% |

方法、逐相位时长与复现命令见 `docs/四典型路口最优调度方案.md`（含图）；
批量复现脚本：`backend/scripts/webster_opt_4isect.py`（把本目录四工程作为输入可重跑）。

## 在平台中加载

1. 启动后端（`backend/` 下 `python -m uvicorn app.main:app`）；
2. `GET /api/v1/networks` 会列出 `案例路口1~4`；
3. 网页顶部路网下拉选择任一案例路口 → 选方案/场景 → 启动仿真即可单点演示。

> 提示：单点路口的目的是"单路口信号配时/控制"研究演示（对应赛题任务1-2）。
> 多路口"路网协同"请用 `base_network` 或其它片区路网。
> 每个工程原配时可在 SUMO GUI（`demo_N.sumocfg`）中观察；算法效果对比参考上表。
