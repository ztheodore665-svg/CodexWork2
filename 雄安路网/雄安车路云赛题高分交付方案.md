# 雄安新区“城市大脑”车路云一体化赛题高分交付方案

> 适用赛题：XH‑202613《面向雄安新区“城市大脑”的车路云一体化协同管控算法与仿真平台研究》
>
> 目的：基于赛题要求与现有 `REQUIREMENTS.md`，明确最终应交付什么产品、产品中应包含哪些模块，以及如何围绕评分标准尽可能拿高分。

---

# 1. 总体结论

当前系统已经具备较完整的工程基础，包括：

- 雄安路网仿真
- 三套交通调度方案
- 前后端系统
- REST API
- WebSocket 实时推送
- 实时可视化
- 指标采集
- Docker 容器化
- 算法插件化
- MAPPO / STGCN / SCOOT
- Webster / MAXBAND
- 动态 Dijkstra / K 短路 / 负载均衡

但如果完全按照当前 `REQUIREMENTS.md` 实现，容易成为：

> 一个功能较完整的交通仿真与算法平台

而赛题真正希望看到的是：

> **面向雄安新区“城市大脑”的车路云协同交通数字靶场、智能决策与标准化评测平台。**

因此后续开发重点不应该继续无限增加算法，而应该补齐以下五个关键方向：

1. **云—边—端协同架构**
2. **扰动场景注入**
3. **Benchmark 基准测试体系**
4. **标准化测试与报告体系**
5. **高冲击力比赛演示模式**

---

# 2. 建议的最终产品定位

## 2.1 产品名称建议

### 雄安城市大脑·车路云协同交通数字靶场与智能管控评测平台

不建议仅使用：

> 雄安交通调度仿真平台

更适合比赛的完整产品定位为：

> **面向雄安新区“窄路密网”交通场景，集真实路网数字孪生、扰动场景生成、云边端协同决策、AI 交通管控、实时可视化、算法基准测试和标准化报告生成于一体的车路云协同管控验证平台。**

# 3. 赛题真正要求解决的三个核心问题

整个产品应该围绕以下三条主线构建。

## 3.1 高保真、可编程的雄安交通数字靶场

需要解决：

- 雄安新区窄路密网
- 高密度交叉口
- 复杂交通流
- 机非混行
- 多类车辆
- 真实信号配时
- 施工占道
- 大型活动
- 应急交通
- 事故等突发扰动

目标是让算法不是在理想化路网中运行，而是在接近真实雄安交通环境的仿真场景中运行。

---

## 3.2 云—边—端异构协同决策

系统不应该只体现：

```text
前端 ↔ 后端 ↔ SUMO
```

而应明确体现：

```text
Cloud
  ↓
Edge / RSU
  ↓
Vehicle
  ↑
状态反馈
```

即：

- 云端负责全局优化
- 边缘负责局部实时控制
- 车端负责执行和反馈

---

## 3.3 面向地方标准的 Benchmark 与量化评估

系统不仅要：

> 能运行算法

还要能够回答：

> 这个算法究竟比传统方案好多少？

最终应形成：

```text
场景
  ↓
交通负荷
  ↓
算法
  ↓
多次重复实验
  ↓
指标统计
  ↓
算法对比
  ↓
自动报告
```

最终形成可以直接作为测试规程参考的标准化实验体系。

# 5. 将现有三套算法重新包装为“云边端协同”

当前三套调度方案技术基础已经不错，但现在容易给人感觉是三个独立算法 Demo。

应该重新解释。

---

## 5.1 Cloud 云端

负责：

- 全局交通状态获取
- STGCN 短时交通流预测
- 区域拥堵识别
- 全局绿波走廊生成
- 区域路由协调
- 全局策略下发

可使用现有：

- STGCN
- 全局指标
- 动态路由
- MAXBAND
- 区域协调逻辑

---

## 5.2 Edge 边缘 / RSU

负责：

- 单路口或局部路网控制
- 排队检测
- 信号灯相位调整
- 本地协调
- 云端失效情况下的降级运行

可使用现有：

- MAPPO
- SCOOT
- Webster
- TOD

---

## 5.3 Vehicle 车端

负责：

- 状态上报
- 接收云/边控制建议
- 路线执行
- 重新规划
- 应急车辆优先
- 公交/网约车/配送车队调度

可使用现有：

- 动态 Dijkstra
- K 短路
- 负载均衡
- 受限区域
- 自动重路由

# 16. 不要把 MAPPO + STGCN 简单描述成“用了 AI”

现有 Scheme 2 本身设计已经较强。

建议将其包装为：

# 预测驱动的分层多智能体协同控制

逻辑：

```text
STGCN
预测未来交通状态
      ↓
MAPPO
多路口协同决策
      ↓
SCOOT
安全降级
```

核心创新不是简单地：

> 我们使用了 MAPPO。

而是：

> **Prediction + Coordination + Fallback**

即：

1. 有预测
2. 有多路口协同
3. AI 失效可以安全降级

这比单纯强调网络结构更具有工程价值。

# 31. 一句话总结

当前系统无需推倒重做。

应从：

> **v1.0：交通仿真 + 调度算法平台**

升级为：

> **v2.0：雄安车路云协同数字靶场 + AI 决策 + 标准化评测平台**

后续最值得投入时间的五件事是：

1. **云边端**
2. **扰动注入**
3. **Benchmark**
4. **标准化**
5. **比赛演示**

现有的：

- MAPPO
- STGCN
- SCOOT
- Webster
- MAXBAND
- Dijkstra
- K 短路
- 负载均衡

已经足以支撑算法深度。

真正决定高分的，是把这些技术组织成一个：

> **可运行、可复现、可比较、可量化、可演示、可标准化的完整车路云产品。**
