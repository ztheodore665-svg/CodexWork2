\section{作品概述}

\subsection{创作背景}

区块链通过分布式账本保存交易和状态记录，使链上信息公开可查且难以篡改。以太坊等区块链平台支持智能合约，开发者可以将交易规则、资产管理和协议逻辑编写成链上代码，由网络节点按照既定规则验证和执行。用户调用智能合约时会发起一笔交易，交易哈希是这笔交易在链上的唯一标识，事件日志记录资产转移等关键事件，执行轨迹（Trace）则记录交易内部的函数调用和状态读写过程。这些数据共同构成攻击复盘和漏洞定位的证据。\par

智能合约直接管理链上资产，一旦出现缺陷，攻击者可能在短时间内转移大量资金。根据项目报告引用的 SlowMist Hacked 统计，公开区块链安全事件累计损失已超过 378 亿美元，事件数量超过 2160 起；2025 年 Bybit 事件单次损失约 15 亿美元。攻击发生后，安全团队需要尽快回答“钱是怎么被转走的、攻击利用了什么漏洞、应该如何修复”等问题。传统工具可以拉取交易或展示轨迹，但很难进一步判断应该先查哪笔交易、漏洞函数在哪里以及补丁是否有效。\par

因此，本项目开发 AttackPilot 链上攻击复盘平台，面向安全分析人员、合约开发者以及希望理解链上攻击本质的研究人员，服务于链上事故复盘、漏洞修复和安全案例教学。系统利用大语言模型和多智能体分析，将分散的链上证据整理为易理解的复盘分析报告。

\subsection{作品简介}

AttackPilot 的目标是完成从交易输入到复盘报告的自动化分析。用户可以提交单笔交易或多笔交易列表，也可以直接选择 SushiSwap、ApeCoin 等真实缓存案例。系统依次完成攻击交易检测、根因定位、相似案例检索和补丁验证，并保留对应的链上证据，逐步回答“是否存在攻击、攻击路径是什么、根因函数在哪里、修复是否有效”。\par

作品将交易取证、智能体分析、补丁验证和证据归档组织成一条连续流程。平台集中展示 Agent 状态、任务日志、关键交易、攻击路径、证据来源、补丁结果和结构化报告，并提供报告导出、取证助手、漏洞教学和案例知识库能力。作品的开发目的不是简单输出一个可疑函数列表，而是把“提出假设、查找证据、验证结论、修正判断”的安全分析过程转化为可理解、可复核的应用流程。

\subsection{目标受众与使用场景}

\begin{itemize}[leftmargin=2.5em]
  \item \textbf{安全分析人员：}用于可疑交易初筛、攻击路径复盘、证据核验和报告整理。
  \item \textbf{智能合约开发者：}用于查看根因函数、触发条件、修复建议，并检查补丁能否阻断原始攻击。
  \item \textbf{学习与研究人员：}用于从真实案例中学习攻击步骤、PoC 思路、链上信号、漏洞机制和修复方式。
  \item \textbf{教学与演示场景：}通过缓存案例和漏洞教学视图，将复杂 Trace、资金流和调用关系组织成易理解的学习材料。
\end{itemize}

\section{设计理念}

\subsection{设计主题与创意来源}

本项目基于中山大学软件工程团队已被 ISSTA 2026 接收的论文 TracePilot 所提出的多智能体跨交易故障定位方法，构建面向区块链攻击复盘的 AttackPilot 平台。作品以“证据驱动的链上攻击复盘”为主题，将安全专家在实际复盘中使用的“提出假设、查找证据、验证结论、修正判断”过程转化为闭环式智能体工程（Loop Engineering）流程。

\subsection{核心设计思路}

系统以“交易取证—智能体分析—补丁验证—证据归档”为主线。首先收集交易收据、事件日志、资金变化、执行 Trace 和合约源码；随后由宏观交易分析智能体识别相关交易、地址角色、资金流向和状态依赖；再由微观 Trace 智能体围绕可疑函数和调用路径展开分析，结合源码、参数、返回值、存储读写和内部调用定位漏洞函数；最后由补丁智能体生成修复建议并在 Tenderly 中重放原攻击，审查智能体根据验证结果检查结论是否成立。

当补丁不能阻断攻击或证据链不完整时，系统会回到前序分析阶段继续查证；验证通过后生成结构化报告，并保留交易 Hash、Trace 节点、函数位置、工具调用和补丁结果等证据。完成的复盘报告还会沉淀为案例知识，为后续分析、修复和教学提供参考。

\subsection{所使用的技术和系统架构}

平台采用“视图层—业务逻辑层—数据层”的分层架构。视图层基于 React 18、Vite 5 和 TypeScript 5 实现，提供交易输入、案例选择、任务控制台、Agent 状态、攻击路径和报告导出等交互页面。业务逻辑层以 FastAPI 承接 REST API 请求，并通过 WebSocket 实时推送任务状态和分析日志；多智能体引擎负责交易筛选、宏观分析、Trace 调试、根因定位、补丁生成、重放验证和结果审查，并通过 MCP 工具集按需获取 Trace 节点、源码和状态变化等证据。\par

数据层连接 JSON-RPC、Etherscan、Tenderly 以及 Phalcon/Tenderly Trace 服务，获取执行 Trace 和合约源码；使用 PostgreSQL 15 持久化任务状态、最终报告和日志记录，使用 Redis 7 作为运行时缓存，用于加速上下文片段和高频状态读取；案例知识库采用关键词与向量混合检索，为智能体召回相似漏洞、历史案例和修复经验。系统通过 Docker Compose 启动后端、PostgreSQL 和 Redis，前端开发阶段由 Vite 单独运行。

\section{区块链技术应用}

\subsection{使用的区块链平台和版本}

作品面向 Ethereum 及 EVM 兼容链上的真实交易数据，当前配置支持 Ethereum 和 BNBChain 等网络。系统使用 JSON-RPC 获取交易、收据、事件和执行 Trace，使用 Etherscan 类服务获取合约源码与 ABI，使用 Phalcon/Tenderly Trace 获取和分析调用轨迹，并使用 Tenderly Simulation API 重放攻击交易和验证补丁。\par

运行环境和相关软件版本为：后端 Python 3.10，前端 React 18、Vite 5、TypeScript 5，数据层 PostgreSQL 15、Redis 7，服务通过 Docker Compose 编排；模型调用使用 OpenAI-compatible API，当前部署接入 DeepSeek 系列模型。项目没有另行发行代币或搭建新链，而是利用区块链公开账本、智能合约执行轨迹和模拟环境完成安全分析。

\subsection{区块链主要存储的信息类型}

平台读取和组织的区块链信息包括交易 Hash、区块号、交易收据、成功状态、调用者与被调用者、函数选择器、内部调用层级、事件日志、代币和原生币余额变化、合约地址、函数签名、源码位置、状态读写以及模拟回放结果。\par

这些链上事实会进一步形成攻击候选、交易角色、攻击阶段、根因假设、补丁结果和报告证据引用。链上数据仍以公链节点、扫描器或模拟服务返回结果为依据；任务状态、日志、最终报告和缓存知识由应用层进行管理。

\section{作品特色与创新}

\subsection{作品的创新点}

\begin{enumerate}[leftmargin=2.8em]
  \item \textbf{从棘手的人工分析扩展为自动化的跨交易智能体复盘。}系统将分析对象从单笔交易扩展到完整攻击事件，自动完成交易取证、上下文组织、Trace 调试、根因推理和结果审查。
  \item \textbf{从多个可疑候选根因转变为可验证的确定性结论。}系统基于 MCP 实现动态 Trace 探索，逐步缩小分析范围，聚焦细粒度交易事实，并通过可复现的补丁测试验证判断可靠性。
  \item \textbf{将一次性报告沉淀为可复用知识库。}系统将关键交易、漏洞类型、根因函数和补丁结果沉淀为案例知识，并通过关键词与向量检索召回相似漏洞和历史案例。
\end{enumerate}

\subsection{与同类作品的区别与优势}

传统工具通常提供交易浏览、Trace 展示或静态候选位置，用户仍需人工串联交易、源码、资金流和修复结果。AttackPilot 将交易输入、链上取证、智能体过程、攻击路径、证据审查、补丁验证和报告导出统一到同一工作区，既服务于真实安全事件复盘，也服务于协议修复辅助和安全案例教学。\par

在项目报告所述的 149 个真实 DApp 安全事件上，AttackPilot 核心算法的 Recall@Top-1、Recall@Top-3、Recall@Top-5 均为 71.14\%，Precision 为 77.78\%。平均端到端分析时间为 4,893.81 秒，约 1.36 小时；项目报告中人工专家完成一次复盘平均需要 16.7 小时，系统将复盘时间减少约 91.8\%。以上结果属于报告中的固定实验设置。

\subsection{作品难点及解决方案}

\begin{enumerate}[leftmargin=2.8em]
  \item \textbf{跨交易关系复杂：}综合交易日志、资产变化、地址交互和资金流图识别攻击者、受害合约、池子和路由合约等角色，判断交易之间的状态依赖。
  \item \textbf{Trace 体量大：}以外部调用 Trace 作为骨架，先建立浅层执行视图，再围绕资产异常、状态变化、权限判断或价格计算节点选择性展开。
  \item \textbf{多智能体需要共享状态：}用结构化任务状态维护攻击阶段、待解问题、已验证证据和被否定假设，并持久化任务、报告和日志。
  \item \textbf{补丁不一定有效：}把补丁编译和攻击重放纳入反馈环，区分补丁实现问题和根因判断问题，分别反馈给补丁智能体或分析智能体。
  \item \textbf{结论需要可核验：}将结论绑定到交易 Hash、攻击阶段、资金流变化、Trace 节点、函数源码、状态读写、工具调用和补丁重放状态。
\end{enumerate}

\section{创作总结}

\subsection{开发过程中的收获与经验}

项目将 TracePilot 研究方法转化为可运行的应用平台，使团队认识到安全分析不仅需要模型能力，也需要稳定的数据模型、明确的任务状态、清晰的交互设计和可重复的验证过程。通过把最终答案、分析过程、原始证据和验证结果同时呈现，用户能够判断系统结论是否值得采信。

\subsection{区块链使用的体会与反思}

区块链数据公开且可追溯，但公开不等于易理解。单独查看一笔交易或一条事件日志，往往无法解释攻击者如何准备状态、如何触发漏洞以及资产最终流向何处。只有把交易、事件、内部调用、状态变化和源码位置组织起来，才能形成能够支撑安全判断的证据链。大模型可以提高阅读、归纳和任务规划效率，但不应替代链上事实、源码位置和可执行验证。

\subsection{作品的不足之处及改进方向}

当前版本依赖外部 RPC、扫描器、Trace 服务、Tenderly 和模型接口；完整新案例分析需要网络和相应配置，演示主要依赖已导入的 SushiSwap、ApeCoin 等缓存案例。部分复杂合约仍可能存在源码缺失、数据接口失败或模拟环境差异。后续将完善多链适配、密钥与权限管理、更多可量化评测、在线部署、报告模板化导出和更细致的人工复核机制。
