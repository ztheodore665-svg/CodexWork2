# 2026-10-19 阶段 2：结构化 + 向量混合检索

## 交付（W2-1 / W2-2 / W2-3 全部落地）

**W2-1 结构化解析**
- `app/agent/rag/time_parser.py`：中文时间表达 → `TimeRange`（纯函数）。规则负责"算数"，LLM 负责"认字"，冲突以规则为准（记 `time_source`）。
- `app/agent/rag/filters.py`：`StructuredFilter` / `BBox` / `bbox_from_center` —— 解析结果 → SQL 的唯一中间表示。
- `data/time_cases.jsonl`：22 条用例**每条自带 today**（否则"上个月/去年"跨年后全红）。
- 两类主动放弃：农历节日（算不准）→ 返回 None；推断年份落在未来 → 往前挪一年。

**W2-2 混合检索**
- `document_service.py`：`_filter_clauses`（时间**区间相交** + 缺字段放行）、`_bbox_clauses`（必须 cast 数值）、`lexical_search`（覆盖率 = 命中词数/总词数）、`coverage_expr`（单独抽出以便不连库编译断言）。
- 迁移 `0004`：GIN(JSONB) 支持 `?|` + GIN(gin_trgm_ops) 支持 ILIKE。仍**不建 HNSW**（先图后过滤可能返回 0 条）。
- `retriever.py`：向量路 → **过滤兜底**（命中 < filter_min_hits 就补一次不过滤检索）→ 词面路 → **各自 min-max 归一化后加权**（0.65/0.35）。本阶段刻意不做 RRF（设计文档排在 W4-3）。
- `ports.py` 拆成 `VectorSearchPort` / `LexicalSearchPort`，允许只实现一路。

**W2-3 SSE 流式 + 前端**
- `app/api/v1/agent.py`：POST + text/event-stream，`X-Accel-Buffering: no`，每事件前检查 `is_disconnected()`；**中断时必须显式 `trace.finish_run(status="interrupted")`**（break 会让生成器停在 yield，Run 永远 running）。
- `pipeline.run_stream` 产出 parsed/evidence/delta/restart/done；**非流式 `run` = 丢弃流式全部事件**（保证评测口径与线上一致）。
- 前端 React18+Vite5+TS：`streamChat` 按 `\n\n` 切帧 + buffer 半帧；AbortController = 停止生成。

## 关键决策
1. **时间过滤用"区间相交"不是"包含"**，且无时间字段的文档放行（否则地点文档被整体误杀）。
2. **过滤必须配兜底**：漏召回比多召回贵得多；`retrieve_debug.filter_fallback` 是排查第一现场。
3. **覆盖率当主分数**，`similarity()` 只用于同分排序 —— pg_trgm 中文效果依赖 locale，不可复现。
4. **内存替身里再实现一遍过滤**（`tests/fakes.py`）：两份实现逼着 SQL 与 Python 语义一致。
5. `degraded=True` 时丢弃 LLM 的 places/themes，**保留规则算出的时间**（否则离线模式永远测不到过滤路径）。

## 踩坑（已修）
1. `Document.metadata_json.astext` 不存在（ORM InstrumentedAttribute 不代理 JSONB 的 astext）→ 用 `cast(Document.metadata_json, String)`；`meta["key"].astext` 才可用。
2. ruff 自动修复 30 处历史问题后必须重跑全量 + `ruff format`。
3. `AsyncGenerator[str, None]` 作为异步生成器返回类型；抽象方法体里**不要写 yield**（mypy 会报 generator 类型不符）。
4. `typing.cast` 要写全名 —— 本模块 `from sqlalchemy import cast` 是 SQL 的 CAST。
5. `reduce(operator.add, ...)` 不能用 `sum`（内置 sum 以 int 0 起步会污染 SQL）。
