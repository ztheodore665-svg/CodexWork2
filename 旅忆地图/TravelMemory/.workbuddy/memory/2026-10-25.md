## 踩到的坑（下次直接绕）

1. **pytest exit code 会被安全钩子置 1**，末尾那行 `[safe-delete]...` 不是失败。
   **以 `--junit-xml` 里的 `failures="0"` 为准**。
2. **`fireEvent.change(input, { target: { files } })` 静默失效**：
   `input.files` 是只读 FileList，没有 setter，赋值不报错也不生效。
   必须用 `Object.defineProperty(input, 'files', { value: [file], configurable: true })`。
3. **jsdom 的 `File` 没有 `.text()`**（浏览器有）。不补会抛 TypeError 被 catch 兜成
   "读不出这个信物"，于是每条用例只能测到"打不开"这条路径。用 `FileReader` 补齐。
4. **`waitFor` 要等"结果出现"，不要等"loading 消失"**：`verifying` 在第一轮 render
   之后才翻 true，"找不到『正在验证』"在异步开始前就成立 → waitFor 立刻通过，
   断言跑在状态更新之前。
5. `getByText` 对**重复出现**的文案会报 multiple elements —— 三条 CheckItem 共用
   同一句失败原因，要用 `getAllByText`。
6. mypy：`session.execute(...).scalars().all()` 是 `Sequence`，声明 `list[Trip]`
   要包一层 `list(...)`。

## 第三班（夜间无人值守）：照片为底层、行程为视图

提交 `eb1330f`。人类实测反馈"导入失败 + 行程删不掉"，本轮把架构翻过来。

### 导入失败的根因（值得记一辈子）

`frontend/vite.config.ts`：
```ts
const API_BASE = process.env.VITE_API_BASE ?? 'http://localhost:8000';  // 错
const API_BASE = process.env.VITE_API_BASE || 'http://localhost:8000';  // 对
```
`.env.local` 里 `VITE_API_BASE=` 是**留空**（语义 = "走同源相对路径 + 开发代理"），
而 `??` 只在 null/undefined 时兜底 —— **空串会原样穿过**，代理 target 变成 `''`，
于是 dev server 下每一个 `/api` 请求都静默失败。

难查在哪：后端直连完全正常（curl 8000 上传成功），只有浏览器里失败；
失败信息是"照片导入失败：HTTP 500"一类的泛化文案，看不出是代理。
**凡是"留空表示用默认值"的环境变量，一律用 `||` 不要用 `??`。**

### 新架构（后端）

| 端点 | 说明 |
|---|---|
| `POST /photos/import` | **只写 Photo 表**，不再触发 trip_cluster；`trip_ids` 从响应里删除 |
| `GET /api/v1/photos` | 照片库，按 `taken_at` 倒序（无时间排末尾），明确回 `has_location` |
| `PATCH /photos/{id}/location` | 补标。`location_source='user'`、`confidence=0.8`（比 EXIF 0.9 低一档） |
| `POST /trips/{id}/photos` | **全量快照**式分配（不猜增量 → 不出幽灵条目） |
| `DELETE /trips/{id}` | 只删 Trip + TripItem（外键 CASCADE），**绝不碰 Photo** |
| `DELETE /trips/{id}/photos/{photo_id}` | 解除单张关联 |

几个关键判断：
- `has_location` 要 `lat` 与 `lng` **都有**才算。只有 lat 没有 lng 是可能的脏数据，
  按单字段判会让前端显示"已定位"却画不出点。
- 补标置信度 0.8 < EXIF 0.9：用户手点是**当事人陈述**不是设备记录，
  而这个值参与地理模糊半径计算，虚高会让"承诺半径"名不副实。
- 分配接口顺手把 `source` 提升为 `manual`，让它退出 `rebuild_user_trips` 的删除范围。
- 外键方向别看反：`TripItem.photo_id` 的 CASCADE 是"删照片带走关联"，
  与"删行程不碰照片"是两个方向。`test_delete_trip_keeps_photos` 连真库钉死它。
