# 产品优化提案：从"能聊照片的地图"到"会作证的旅行记忆"

> 状态：提案。基于 2026-11 的公开市场信息与三篇论文，回答两个问题：
> 产品设计上哪里值得改、三篇论文的技术怎么用才不变成装饰。
>
> 结论先放这里：**三篇论文一个都不要原样搬**。ChatEval 的"辩论"在你的场景会放大偏见，
> RECONCILE 的"多模型圆桌"你没有多模型，AgentChain 的"链"你没有对手方。
> 但它们各自有一个**机制**可以被改造成产品能力，见 §4。

---

## 1. 先看市场：你的三个功能，两个已经是标配

| 能力 | 2026 年的市场状态 | 代表 |
| --- | --- | --- |
| 照片 → 地图 / 足迹 | **标配**。自动轨迹、相册足迹、3D 地球都有 | Polarsteps（自称 1700 万旅行者）、高德"时光地图"、百度"相册足迹"、一生足迹、Journeys、Photo Map |
| 旅行手账 / 旅行书 | **红海**。AI 规划 + 协作 + 打印成书是标准套餐 | TripMemo（2026-01 上线，1 万+ 下载，4.6/5）、Polarsteps Travel Books、FindPenguins、Day One |
| 年度回顾 | **标配**。Polarsteps Unpacked、高德/百度年度报告都在做 | 同上 |
| "和照片对话" | **已被大厂商品化** | Google Photos "Ask Photos"（Gemini，据 2026 年报道已扩到 100+ 市场、17 种语言）；AI Gallery（离线端侧，5 万+ 下载）；Dazzle（2026-09，读相册的个人助手） |
| 多人共享记忆 | **新兴**，但已有人做 | OurTales（一张照片多人补故事、分歧并列保留、置信度由本人标注）、Lugelo、Yoree |

**这意味着什么**：如果产品介绍的第一句是"用 AI 和你的旅行照片聊天"或"自动生成旅行地图"，
它在 2026 年没有任何辨识度——前者 Google 免费送，后者 Polarsteps 做了十年。

### 1.1 真正的空位：信任

Booking.com 2025 年《全球 AI 态度报告》（33 个市场、37,325 人）：

- **89%** 想在旅行规划里用 AI；
- 只有 **12%** 放心让 AI 独立做决定；
- 只有 **6%** 完全信任 AI；
- **42%** 会反复核对 AI 给的答案。

同一时期，Gartner（2025-06）预测：到 2027 年底，**超过 40% 的 agentic AI 项目会被取消**，
原因是成本攀升、商业价值不清、风控不足；并点名"agent washing"——把聊天机器人改个名就叫 Agent。

再看一个行业事实：ALCE 基准（Gao et al., 2024）测出，即便是 GPT-4，在复杂综合任务上
**约 50% 的陈述没有被它引用的段落完全支持**。也就是说，"有引用"和"引用是对的"是两件事，
而市面上的产品基本只做到了前者。

**结论：市场不缺"更会规划"的 AI，缺"敢让你核对"的 AI。**
你的项目恰好已经有三样别人没有的东西：EXIF 重建的行程、逐句引用、原图不上云。
问题是这三样现在都藏在架构里，用户看不见。

## 2. 定位：把"隐私 + 引用"从架构承诺变成可见产品

### 2.1 一句话

> **不替你决定去哪儿，只替你记住去过哪儿——并且证明给你看。**

英文可用：*A travel memory that shows its receipts.*

### 2.2 三个 job（用户真正雇它做的事）

| Job | 用户原话 | 现在产品怎么答 | 应该怎么答 |
| --- | --- | --- | --- |
| **回访** | "去年秋天那趟到底去了哪几个古镇？" | 一段文字 + 引用列表 | 一句话结论 + 地图上高亮 3 个点 + 3 张照片 |
| **求证** | "我真的去过龙门石窟吗，还是我记混了？" | 答"去过"或拒答 | 答"没有——那是 2025 年 3 月，不在去年秋天"+ 展示那张照片的日期 |
| **分享** | "把这次行程发给我妈" | 分享链接 / 信物 | 一张带证据的卡片，她不用装 App 就能看，还能验证没被改过 |

三个 job 的共同点：**用户要的不是"更多内容"，是"更可信的确认"**。
这决定了产品的主界面不该是聊天框，而是**地图 + 记忆卡**；聊天只是入口。

## 3. 产品结构：三个循环，而不是一个聊天框

```
        ┌──────────── ① 重建循环（导入即惊喜）────────────┐
导入照片 → 重建行程 → 首屏展示"3 趟旅程 / 47 个地点 / 12 个可回答的问题"
        └───────────────────────────────────────────────┘
                              ↓
        ┌──────────── ② 追问循环（冷启动靠它）───────────┐
Agent 主动问 3 个它答不出的问题 → 用户一句话回答 → 写入记忆 → 立刻生成一张记忆卡
        └───────────────────────────────────────────────┘
                              ↓
        ┌──────────── ③ 分享循环（增长靠它）─────────────┐
生成带证据的卡片 → 同行者/家人打开 → "我也有一张那天的照片" → 邀请贡献 → 回到 ①
        └───────────────────────────────────────────────┘
```

三个循环对应三个指标：激活（首日产生一次有证据的回答）、留存（每周回访旧旅程）、增长（分享卡带来的新贡献者）。

**为什么不是聊天优先**：聊天框的空状态是产品最大的敌人。
用户不知道能问什么，第一句问"你好"就流失了。地图和卡片能自己说话。

## 4. 五个优化点（按优先级）

### P0-1 证据化答案卡

**问题**：现在答案是 Markdown 文本 + 下方证据列表，用户要自己把句子和照片对上。

**做法**：

```
你去年秋天去了乌镇和西塘。        🟢 已核验
[照片1 乌镇 10-02] [照片2 西塘 10-03] [地图缩略图]
▸ 依据（2 条）   ▸ 这句话是怎么来的
```

- 点句子 → 高亮对应照片；
- 点照片 → 地图 flyTo（你已有）；
- 存疑句用黄色下划线，不删，但标出来。

**成本**：前端改造为主，后端只需把 `blocks` 的 `index` 映射到前端可渲染的证据条。

**指标**：依据展开率、用户纠正率（"不对，那是另一趟"的反馈数）。

---

### P0-2 数据小票（Data Receipt）

**问题**："照片不搬家"是你的立论基础，但用户完全感知不到。微软 Recall 的教训很直接：
**本地处理不等于用户信任**——用户要的是"看得见、能控制、能删除"。
Recall 最初默认开启、无可见指示，遭到强烈反对后改为 opt-in + Windows Hello + 排除列表。

**做法**：每条回答底部一行小字，可展开：

```
本次回答用到本机 12 张照片 · 上传 0 张 · 未调用外部检索
▸ 查看用了哪 12 张   ▸ 本次排除 3 张（含 1 张人像）
```

**为什么这是差异点**：所有竞品都说"隐私优先"，但没人给你一张小票。
这条小票把架构承诺变成了可截图传播的产品语言。

**成本**：极低。`PipelineState.blocks` 里已经有本轮用了哪些证据，加一个计数与排除原因即可。

**指标**：信任问卷（"你相信它没有上传照片吗" 1-5 分）、分享意愿。

---

### P0-3 主动追问（解决冷启动）

**问题**：RAG 的语料是 caption，caption 只有"西湖边散步"，没有"和谁、为什么、当时什么感觉"。
用户不提问，语料永远长不出来。

**做法**：导入完成后，Agent 挑 3 个**它答不出但照片能定位**的问题：

- "这张 2024-10-03 在西塘拍的照片，同行的是谁？"
- "这趟是出差顺路，还是专门去的？"
- "这家店叫什么？照片里只拍到了招牌的一角。"

用户一句话回答 → 写入 `memory_item`（你已有三层记忆）→ 立刻生成一张记忆卡作为奖励。

**为什么有效**：这是把"用户教育"伪装成"Agent 求教"。用户回答一次，就知道以后能问什么；
同时语料从 caption 升级为"人讲的故事"，检索质量直接受益。

**成本**：需要一个"可问性打分"（照片有时间地点、但缺人物/目的/名称），规则即可，不必上模型。

**指标**：首日提问率、记忆条目数、第二周留存。

---

### P1-1 记忆圆桌（RECONCILE 的正确用法）

**问题**：旅行几乎都是多人同行，而记忆天然分歧——"我们到底去没去西湖"、"住的是两晚还是三晚"。
现在的产品只有一个视角：照片。

**做法**：同行者各自加入一趟旅程，每人只贡献**claim + 置信度**（不共享整个相册）：

```
妈妈说：我们去了西湖          [确定]
爸爸说：那天太累了，没去      [记不清]
照片：2024-10-05 西湖边，2 张 [证据]

→ 结论：去了。爸爸记错了。  （置信度加权 + 照片证据）
```

**关键设计：分歧不强行统一**。两种说法并列保留，各自标注置信度，谁说的归谁。
OurTales 已经把这条做成了产品原则（"disagreement is a feature"），说明它不是拍脑袋。

**这是三篇论文里唯一"原样可用"的机制**：RECONCILE 的置信度加权投票，
把"多个模型"换成"多个真人"，把"辩论"换成"各自举证"。
而且它自带增长：邀请同行者就是拉新。

**成本**：中。需要多人权限模型 + 冲突展示。**先做只读对比**（A 的结论 vs B 的结论），
不做协同编辑，避免掉进协作产品的复杂度。

**指标**：每趟旅程的平均贡献者数、分歧卡的查看率、邀请转化率。

---

### P1-2 可验证信物（AgentChain 的机制，C2PA 的格式）

**问题**：你把行程分享出去，对方无法判断这是真实的照片记录，还是 AI 编的故事。
2026 年这个怀疑是合理的——生成一张"看起来去过"的照片太容易了。

**做法**：分享卡带一个签名清单（manifest）：

```json
{
  "claims": [{"text": "2024-10-02 去了乌镇", "evidence": ["sha256:..."]}],
  "photos": [{"hash": "sha256:...", "taken_at": "2024-10-02T18:20:00+08:00"}],
  "auditors": [{"role": "time", "verdict": "supported"}],
  "signature": "ed25519:..."
}
```

接收者用浏览器打开就能看到：哪些句子有证据、照片哈希是否被改过、由谁签的名。

**用 C2PA 兼容格式，不要自造链**。C2PA 在 2026 年已经是相机厂商的标配
（Leica、Sony、Canon、Nikon 部分机型，Google Pixel 10 也会签），浏览器有官方验证器。
你只需要按同样的 manifest 结构导出，就能被通用工具读取——这比"我们用了区块链"有说服力得多。

**但要诚实**：C2PA 本身出过事故（Nikon 因漏洞撤销过证书；2026-08 有研究演示 Android 端可伪造签名）。
所以产品措辞必须是「**可追溯、未被篡改**」，不是「绝对真实」。
这和你阶段 7 的红/灰/绿三态语义一致：灰 = 没验过，不是"假的"。

**成本**：中高。但你的 `privacy/` 与 `zk/` 已经有 Ed25519、哈希链、承诺方案，
主要工作是**定义 manifest 结构 + 写一个浏览器端验证页**，不是从零造密码学。

**指标**：分享卡打开率、接收者验证点击率、由分享带来的新用户。

---

### P2 笔触三选一（ChatEval 的改造）

**问题**：回忆文案有"好不好读"的问题，这是主观的，也是可以付费的。

**做法**：同一次回忆生成三个版本（纪实 / 抒情 / 幽默），用**独立评分**选一版，
而不是让三个 agent 互相辩论。评分维度固定：事实忠实度（硬门槛）、具体细节密度、可读性。

**为什么不能照搬 ChatEval 的辩论**：2025 年的后续研究（*Judging with Many Minds*, EMNLP 2025 Findings）
发现，多 Agent 辩论在首轮之后会**显著放大**位置偏见、冗长偏见等固有偏差，并在后续轮次持续；
meta-judge（独立打分再聚合）反而更抗偏。另有研究观察到两人评审团可能优于三人（减少 groupthink）。
所以：**独立打分 + 固定 rubric + 一轮定胜负**，不要吵。

**成本**：低（只影响文案生成，不影响事实回答）。适合作为订阅点。

## 5. 三篇论文：取什么、不取什么、被什么推翻

| 论文 | 表面用法（别做） | 正确用法（做这个） | 2025-26 的反证 / 修正 |
| --- | --- | --- | --- |
| **ChatEval** | 三个 Agent 辩论判断回答好坏 | ① 离线评测：给答案质量打分；② 文案三选一的独立评审团（P2） | 辩论会放大偏见；两人评审团可能优于三人；用独立打分替代多轮辩论 |
| **RECONCILE** | 多模型圆桌辩论出答案 | 多人记忆圆桌：置信度加权 + 分歧并列（P1-1） | 它的结论"多样性来自模型来源"在单人产品里无法复现；换成"真人来源"才成立 |
| **AgentChain** | 链、代币、质押、VRF 共识 | 判定留证 + 多审计员背书 + 签名清单（P1-2） | 单用户产品没有对手方，共识无对象；C2PA 是现成的、可互操作的替代 |

**一句话**：借机制，不借基础设施；借问题定义，不借实验设置。

## 7. 界面层的五个具体改动

1. **首屏不是聊天框**：地图 + 三张旅程卡 + 一行"你可以问我：去年秋天去了哪些古镇？"
2. **空状态给样例问题**，且样例问题来自用户自己的数据（"你在西塘拍过 4 张照片，要看看吗？"）。
3. **答案卡固定三段式**：结论句 / 证据条 / 数据小票。任何回答都不例外，形成肌肉记忆。
4. **"不知道"是一等公民**：拒答时给出"我能确认的"与"我不能确认的"两栏，并给一个可执行的下一步
   （"补一张那天的照片，或者告诉我同行的是谁"）。
5. **分享卡默认不带人脸**：人像默认模糊，可逐张解锁。这是隐私产品该有的默认值，也是传播时的信任信号。

## 8. 指标与三个实验

### 8.1 北极星

**"每周被回访的旧旅程数"**（Weekly Revisited Trips）。
它同时度量留存与核心价值：用户回来，是因为这里真的存着他的过去。

### 8.2 支撑指标

| 层 | 指标 | 目标 |
| --- | --- | --- |
| 激活 | 导入后 10 分钟内产生 1 次"有证据的回答" | ≥ 60% |
| 信任 | 答案卡"依据"展开率 | ≥ 35% |
| 信任 | 用户纠正率（点"不对"） | ≤ 5%，且逐月下降 |
| 留存 | 次周回访旧旅程 | ≥ 25% |
| 增长 | 分享卡 → 新贡献者转化 | ≥ 8% |
| 成本 | 单次回答成本 | 维持现有预算内 |

### 8.3 三个可做的实验

1. **A/B：数据小票有无**。假设：有小票的用户信任评分 +0.5，分享意愿 +15%。
2. **A/B：主动追问 vs 纯搜索框**。假设：主动追问组首日提问率翻倍，D7 留存 +8 个点。
3. **A/B：存疑标注 vs 直接删句**。假设：标注组的纠错率更高、投诉更少（删句会让用户以为"它没看见"）。

## 9. 路线图（按"能不能演示"排，不按技术难度）

| 阶段 | 做什么 | 出口（可演示） |
| --- | --- | --- |
| 2 周 | 证据化答案卡 + 数据小票 | 录一段 30 秒：问一句 → 出卡片 → 展开小票 → "0 张上传" |
| 4 周 | 主动追问 + 记忆卡 | 新用户导入后 3 分钟内被问 3 个问题，答完立刻看到一张卡 |
| 6 周 | 记忆圆桌（只读对比） | 两个人对同一趟旅程给出不同结论，界面并列展示 + 照片裁决 |
| 8 周 | 可验证信物（C2PA 兼容 manifest + 浏览器验证页） | 把卡片发给没装 App 的人，对方在浏览器里看到"未篡改" |

前两周的东西就足够支撑一次面试演示，且**不需要新模型、不需要新基础设施**。

## 10. 风险

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 功能铺太开，8 周做不完 | 高 | 高 | 只做 P0 两项 + 一个 P1；P2 直接砍 |
| 多人功能把权限模型做复杂 | 中 | 高 | 只做邀请 + 只读对比，不做协同编辑 |
| C2PA 兼容性踩坑 | 中 | 中 | 先做"自有 manifest + 浏览器验证页"，C2PA 字段做兼容映射即可 |
| 大厂（Google）下沉到旅行场景 | 中 | 高 | 押"本地 + 可验证 + 多人"，这三点大厂结构性做不到（云端架构 + 广告模式） |
| 用户不愿贡献记忆 | 中 | 中 | 用"一张卡"作为即时回报；先问 1 个问题，不要一次问 5 个 |

## 11. 一句话总结（面试/路演都能用）

> 2026 年所有人都在做"更会规划"的旅行 AI，但只有 12% 的人敢让它独立做决定。
