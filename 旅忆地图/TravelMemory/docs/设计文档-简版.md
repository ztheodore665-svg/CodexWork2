# 旅忆地图 TravelMemory 设计文档（简版）

## 1. 项目概述

TravelMemory 是一个以个人照片和地图为记忆底座的旅行记忆应用。用户在本地导入照片，系统提取时间、GPS 等元数据，生成地图行程，并由旅行记忆 Agent 根据可检索的个人资料回答回忆问题、提供路线与地点建议。产品面向单用户多设备，提供 Web 端并支持 Capacitor 跨端封装。

## 2. 设计原则

- **隐私优先**：原始照片保留在设备本地；服务端仅接收必要元数据和缩略图。
- **答案可追溯**：事实性回答必须引用检索证据；证据不足时明确拒答。
- **位置一致**：数据库统一存储 WGS84 坐标，地图展示时转换为 GCJ-02，并显式标注坐标系。
- **模块可降级**：推荐、隐私证明等扩展功能通过开关控制，失败不得阻断地图和问答主流程。

## 3. 系统架构

```text
Web / 移动端（React、TypeScript、Vite、Capacitor）
        │ HTTPS / SSE
FastAPI 接口层（参数校验、响应适配）
        │
业务服务（照片、行程、地图、文档、记忆）── Agent 编排（Pipeline / LangGraph）
        │                                      │ 工具调用
PostgreSQL（PostGIS、pgvector、全文检索）   POI / 路线 / 推荐服务
        ├─ Redis：缓存、会话和幂等控制
        ├─ MinIO：缩略图对象存储
        └─ LLM / Embedding 外部模型服务
```

依赖方向为 `Agent → Nodes → Tools → Services → Models`。客户端负责照片选择、EXIF 读取、缩略图生成和地图呈现；后端负责数据持久化、空间查询、检索、Agent 推理及第三方密钥保护。

## 4. 核心模块

| 模块 | 职责 |
| --- | --- |
| 照片导入与处理 | 本地读取照片元数据、生成缩略图；后端异步生成 caption、标签并建立索引 |
| 地图与行程 | 按空间和时间聚合照片点，展示轨迹、行程和地图证据 |
| 检索与记忆 | 组合向量、关键词与时空过滤，管理会话、情景和语义偏好记忆 |
| 旅行 Agent | 解析问题、检索证据、调用地图工具、生成带引用答案并进行自检 |
| 评测与可观测 | 记录请求和工具链路，评估召回、引用、拒答及工具选择质量 |
| 隐私扩展 | 对外分享时可进行位置泛化与精度标注；验证组件以旁路方式运行 |

## 5. 关键数据流

### 照片入库

用户选择照片 → 客户端提取 EXIF/GPS 并生成缩略图 → 上传元数据和缩略图 → 后端任务生成描述与标签 → 建立文本/向量索引 → 地图聚合并形成行程。

### 记忆问答

用户提问 → 时间与地点条件解析 → 混合检索个人文档/记忆 → Agent 按需调用 POI 或路线工具 → 生成带证据编号的回答 → 校验引用并流式返回，前端可同步高亮地图证据。

## 6. 数据与接口约束

- 核心实体包括照片、文档、行程及行程项目、记忆条目与来源；空间字段由 PostGIS 管理，语义向量由 pgvector 管理。
- 数据库保存规范化坐标，前端展示坐标由共享地理模块统一转换。
- Agent 对话使用 SSE 返回流式内容；照片处理和索引通过可重试、幂等的后台任务完成。
- LLM、Embedding 和地图服务统一从后端适配层调用；密钥不得暴露给客户端。

## 7. 质量要求

1. 原图不上传，数据处理链路可追踪。
2. 事实性回答引用率目标为 100%；缺少证据时正确拒答。
3. 照片导入、描述生成和索引任务支持重复执行而不产生重复结果。
4. 地图大数据量渲染使用聚合与图层管理，避免逐点创建大量 DOM 标记。
5. 检索、Agent 工具选择和回答质量均通过离线评测集持续验证。

## 8. 技术栈

前端采用 React、TypeScript、Vite 与 Capacitor；后端采用 FastAPI、SQLAlchemy、Pydantic 和 Alembic；数据层采用 PostgreSQL、PostGIS、pgvector、pg_trgm，并按需使用 Redis 与 MinIO。Agent 从可切换的 Python Pipeline 演进到 LangGraph，RAG 检索与评测逻辑由项目自身实现。
