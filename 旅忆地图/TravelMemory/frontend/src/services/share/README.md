# 分享协议层（W6-4 前端部分）

从 TrailShare（`F:\project\trailshare\docs\REPLICATION.md`，协议 `ts-2026.4`）移植过来的
**定向加密信物**：发送方把一段旅程按可见性过滤后加密，只有指定收件人能解开。

| 文件 | 职责 |
|---|---|
| `crypto/keys.ts` | 一份种子 → Ed25519（签名）+ X25519（KEM） |
| `crypto/sign.ts` | canonical JSON + Ed25519 签/验 |
| `crypto/encrypt.ts` | AES-GCM + X25519/HKDF KEM |
| `crypto/commitment.ts` | 组织承诺（**纯函数**，用 noble 的同步 sha256） |
| `share/schema.ts` | 版本、上限、结构校验、`.trailshare` 文件格式 |
| `share/filter.ts` | 可见性四层层叠过滤（**屏蔽 = 不打包**） |
| `share/pack.ts` | 打包（§6.1） |
| `share/unpack.ts` | 解包（§6.3）+ 视图层（§6.4） |
| `share/prepare.ts` | **TravelMemory 扩展**：地理模糊坐标写进 `PlaceMeta` |
| `fixtures.ts` | 测试夹具（固定种子 / 固定 `NOW` / 固定旅程） |

分层边界照规范 §2.3：`commitment.ts` 是纯函数；`share/*` 不碰数据库；
`prepare.ts` 不直接 import 网络层（模糊函数由调用方注入）。

## 真机验证清单（**尚未执行**，留给人类明早手动跑）

自动化测试只覆盖了协议与密码学，**没有**覆盖"两个浏览器 profile + IndexedDB +
真机相册"的收发全流程。以下每一步都必须由人用真机跑一遍，跑不通就说明还有缺口。

### 0. 前置

- 后端已起：`uvicorn app.main:app --reload`，且 `feature_flags` 里 `privacy = true`
  （否则 `/api/v1/privacy/obfuscate` 返回 404，前端会走降级路径 —— 那条路径也要验）。
- 前端 `npm run dev`，通过 `http://localhost:5173` 打开（`file://` 下 IndexedDB 与
  WebCrypto 都不可用）。

### 1. 两个独立身份

1. **Ctrl+Shift+N 开一个无痕窗口**（窗口 A），再 **Ctrl+Shift+N 开第二个**（窗口 B）。
   > 必须是**两个独立窗口**。同一个无痕窗口里开两个标签页共享 IndexedDB，
   > 等于同一个人，KEM 解封与"非收件人"分支都验不出来。
2. A 窗口 → 好友页，复制"我的公钥"。
3. B 窗口 → 好友页，把 A 的公钥粘进去；反过来也做一次（B 的公钥给 A）。
4. 两边各刷新一次，确认公钥还在（IndexedDB 落库成功）。

### 2. 建旅程（窗口 A）

1. 旅程页 → 新建，标题随便，加**两天**，每天至少一个地点。
2. 每个地点上传**真机相册里的照片** 1–2 张（压缩链路只在真机上才跑得到），
   给其中一张写配文。
3. 给至少两个地点填坐标（有坐标才会走地理模糊）。
4. 刷新页面，确认行程还在（debounce 自动保存生效）。

### 3. 生成信物（窗口 A）

1. 生成信物页 → 选刚建的 Trip。
2. 在可见性树里**取消勾选第二天一天**（验证"屏蔽 = 不打包"）。
3. 收件人勾选 B（不要勾自己，否则"非收件人"分支验不到）。
4. 生成 → 下载 `.trailshare`。
5. **打开下载的文件看一眼**：它是 UTF-8 JSON，应当**搜不到**任何地点名、
   配文、日期 —— 搜得到就说明有东西没进密文。

### 4. 导入与验签（窗口 B）

1. 导入信物页 → 拖入刚下载的文件。
2. 应当看到：**验签通过**、**承诺比对通过**、来源显示为 A。
3. 时间线里**只出现第一天**的地点，且**页面上任何位置都不出现**
   "共 N 组 / 共 N 天 / 共 N 个地点 / 还有 N 个"这类总数暗示。
4. 有坐标的地点应当出现**模糊圈**（半径 = 承诺半径，不是实际偏移量）；
   没坐标的地点不显示圈。
5. 点开照片确认能显示、配文在。

### 5. 反向验证（窗口 B / 窗口 C）

1. 再开**第三个**无痕窗口（窗口 C），不添加任何好友。
2. 把同一个 `.trailshare` 拖进 C → 应当只显示一句"此信物不包含给你的内容"，
   **不显示**"共 1 组"之类的任何包级信息。
3. 人为把文件里某个 `encryptedMeta` 改掉一个字符再拖进 B → 应当报
   "文件已损坏，或不是 TrailShare 信物"，且**不指出是哪个字段坏了**。
4. 把 `version` 改成 `ts-2026.3` 再导入 → 应当报
   "此信物为旧版本，请让发送方重新生成"。

### 6. 接受与降级

1. 窗口 B → 接受 → 记忆库里出现对应地点卡。
2. 重复拖入同一文件 → 应当显示"已接受"，**不重复写记忆**。
3. 把后端 `privacy` flag 关掉（或断网）后在 A 重新生成一次 →
   打包**必须仍然成功**，只是地点没有模糊圈；控制台/结果卡里应能看到降级 warning。
   ⚠️ 这一步是红线：**任何情况下都不允许退化成"发原坐标"**。

### 7. 还没被自动化覆盖、需要人工确认的点

- 照片压缩链路（720px / q0.7）在真机大图上的耗时与内存。
- 同一浏览器进程第二次自动下载可能被拦截（要准备"重新下载"按钮）。
- 移动端断点下可见性勾选树的可用性。
- 两个 profile 之间手工交换公钥时，`ed25519:` 前缀带与不带都要试一次。
