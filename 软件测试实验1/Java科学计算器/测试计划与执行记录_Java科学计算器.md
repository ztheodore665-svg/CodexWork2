# Java 科学计算器测试计划与执行记录

## 1 测试范围与方法

对象为 `Calculator`、`ExpressionParser` 核心逻辑及 `MainWindow` Swing 界面。测试依据项目 README、源码和用户提供的实验要求，采用黑盒功能测试、白盒代码走查、边界值分析、等价类、状态迁移、错误推测、输入模糊测试、兼容性与可用性检查。核心逻辑使用 Java 8 目标编译后通过独立驱动执行；界面按钮布局和键盘支持通过 `MainWindow.java` 走查，未将未连接的自动化桌面操作冒充为执行结果。

测试环境：Windows，JDK 运行环境以当前 `javac/java` 为准；源码目录为本目录；测试日期为 2026-09-17。核心回归驱动：`_qa/CalculatorQaHarness.java`。测试结论仅针对本次源码和打包前核心类，若替换 JAR 或修改源码应重新回归。

## 3 本次发现的缺陷汇总

| 缺陷 | 严重等级 | 触发证据 |
|---|---|---|
| D-01 计算后继续运算状态错误 | S1 | 2+3= 后按 ×、4、=，显示 54 而非 20 |
| D-02 小写 e 破坏科学计数法 | S1 | `evaluateExpression("1e-5")` 返回 7.718281828459045 |
| D-03 负号与幂运算优先级错误 | S2 | `-2**2` 返回 4，常规数学约定应为 -4 |
| D-04 角度模式 tan(90) 未识别未定义点 | S2 | 返回 1.633123935319537E16 而不是错误/未定义提示 |
| D-05 CE 清除范围不符合“当前项”语义 | S2 | 12+3 后 CE 将整式变为 0 |
| D-06 默认区域设置导致科学计数法逗号 | S2 | `Locale.GERMANY` 下输出 `1,234568e+16`，解析器只支持点号 |
| D-07 null 输入参数未统一校验 | S2 | null 可静默写入状态；运算符 null 直接产生 NPE |
| D-08 键盘输入未接入 | S2 | `MainWindow.java` 仅创建按钮并添加 ActionListener，未见 KeyListener、InputMap 或 ActionMap |

## 4 回归建议

修复后优先回归 D-01、D-02、D-05、D-08，再执行异常恢复、区域设置和压力用例。对解析器建议采用词法白名单与明确的运算符优先级定义；对输入 API 做 null/空串/非法 token 校验；对 UI 使用统一 Action 映射，使鼠标和键盘共享同一动作；对三角函数特殊点做容差或定义域策略。长表达式和极大阶乘应增加长度、迭代次数和超时保护。
