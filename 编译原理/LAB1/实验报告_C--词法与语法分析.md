## 一 实验目的

本实验使用 Flex 和 Bison，为 C--语言实现一个词法分析器和语法分析器。程序需要识别 C--源程序中的词法单元，报告词法错误和语法错误，并在输入合法时构造语法树并按照先序遍历打印。通过本实验掌握正则表达式到词法分析器的转换、上下文无关文法的语法分析、抽象语法树数据结构以及错误恢复方法。

## 二 实验环境

实验指导书要求在 Ubuntu 22.04 或其他 Linux 环境中完成实验，主要工具如下：

| 工具 | 用途 |
|---|---|
| GCC | 编译 C 源文件 |
| Flex | 根据 lexical.l 生成词法分析器 |
| Bison | 根据 syntax.y 生成语法分析器 |
| Make | 按 Makefile 完成自动构建 |
| Vim 或其他编辑器 | 编辑实验源文件 |

本程序由 lexical.l、syntax.y、Tree.c、Tree.h 和 main.c 组成，测试文件位于 Test 与 External_Test 目录。

## 三 实验原理

### 3.1 词法分析

词法分析器从左到右读取源程序字符流，根据最长匹配原则将字符序列转换为词法单元。Flex 文件中的正则表达式定义了整数、浮点数、标识符、关键字、运算符、分隔符和注释等模式，匹配成功后通过 return 将对应 token 交给 Bison。

本程序识别的主要词法单元如下：

| 类别 | 内容 |
|---|---|
| 关键字 | struct、return、if、else、while |
| 类型 | int、float |
| 数值 | 十进制、八进制、十六进制整数和浮点数 |
| 标识符 | 由字母或下划线开头的标识符 |
| 运算符 | = + - * / && || ! > < >= <= == != |
| 分隔符 | ; , . ( ) [ ] { } |
| 注释 | // 行注释和 /* ... */ 块注释 |

词法错误统一归为错误类型 A，主要包括未定义字符、非法八进制数、非法十六进制数和不完整的指数形式浮点数。

### 3.2 语法分析

Bison 根据 syntax.y 中的上下文无关文法生成 LALR 语法分析器。文法覆盖了程序、外部定义、结构体、变量声明、函数定义、复合语句、控制语句和表达式。

表达式使用优先级和结合性声明消除常见的移进/归约歧义：

ASSIGNOP < OR < AND < RELOP < PLUS/MINUS < STAR/DIV

赋值运算符为右结合，算术运算符和逻辑运算符按照文法声明的优先级进行分析。IF ... ELSE 使用 LOWER_THAN_ELSE 处理悬空 else 问题。

### 3.3 语法树

Tree.h 中的 Node 结构体保存结点名称、结点类型、源程序行号、词素值、子结点数量和子结点数组。归约时使用 createNode 创建语法树结点，使用 package 将多个子结点组织成数组。分析成功后，printTree 递归访问树并打印非空语法单元及词法单元信息。

## 四 程序设计与实现

### 4.1 编译和运行步骤

进入 Code 目录后，可以直接使用 Makefile 自动编译：

    cd lab1_example_solution1/Code
    make clean
    make

其中，make clean 用于删除上一次构建产生的 parser、目标文件和 Flex/Bison 生成文件；make 会按照 Makefile 自动执行 Flex、Bison 和 GCC。首次编译或修改 lexical.l、syntax.y 后，建议先执行 make clean，再执行 make。

如果不使用 Makefile，也可以逐条执行以下命令：

    flex -o lex.yy.c lexical.l
    bison -o syntax.tab.c -d -v syntax.y
    gcc -std=c99 -c syntax.tab.c -o syntax.tab.o
    gcc -std=c99 -c main.c -o main.o
    gcc -std=c99 -c Tree.c -o Tree.o
    gcc -o parser main.o syntax.tab.o Tree.o

第一条命令根据 lexical.l 生成词法分析器 lex.yy.c；第二条命令根据 syntax.y 生成语法分析器 syntax.tab.c、头文件 syntax.tab.h 和分析报告 syntax.output；接下来的三条命令分别编译语法分析器、主程序和语法树模块；最后一条命令将目标文件链接为可执行文件 parser。

syntax.y 的头部已经包含 lex.yy.c，因此不需要再次单独编译 lex.yy.c，也不要把 lex.yy.o 重复加入最后的链接命令，否则会产生 yylex、yyrestart 等符号重复定义错误。

编译成功后，可以将测试文件路径作为命令行参数传给 parser。例如：

    ./parser ../Test/3.cmm
    ./parser ../External_Test/in/testcase_3

程序会将错误信息或语法树直接输出到终端。若希望保存结果，可以使用 shell 重定向：

    ./parser ../External_Test/in/testcase_7 > ../External_Test/out/my_result

然后可以使用 diff 比较实际结果与参考结果：

    diff -u ../External_Test/out/testcase_7 ../External_Test/out/my_result

### 4.2 程序执行流程

程序入口在 main.c。运行 ./parser 文件名 后，程序依次完成以下工作：

1. 检查命令行参数并打开输入文件。
2. 调用 yyrestart 将 Flex 的输入流切换到指定文件。
3. 调用 yyparse 完成词法分析和语法分析。
4. 若没有词法错误和语法错误，调用 printTree 输出语法树。

词法分析器由 Flex 生成，语法分析器由 Bison 生成；syntax.tab.c 包含生成的扫描器代码，因此 Makefile 最终只需要链接 main.o、Tree.o 和 syntax.tab.o。

### 4.3 词法规则实现

整数规则区分三种形式：

- 十进制整数：0 或不以 0 开头的数字序列；
- 八进制整数：以 0 开头且只含 0 到 7；
- 十六进制整数：以 0x 或 0X 开头且后面至少有一个十六进制数字。

程序额外设置了非法数字规则。例如，09 会被识别为非法八进制数，0x3G 会被识别为非法十六进制数，并输出错误类型 A。

浮点数规则覆盖普通小数和指数形式，例如 1.05e-4。对于 1.05e 这种缺少指数数字的形式，程序单独报告非法浮点数。

块注释使用 Flex 的 COMMENT 状态实现。遇到 /* 时进入 COMMENT 状态，直到读到 */ 才回到初始状态；注释中的普通字符被忽略，换行时更新行号。

### 4.4 语法错误恢复

为了继续报告同一文件中的多个错误，文法中增加了带 error 的错误恢复产生式。例如：

    ExtDecList : VarDec error
    Exp        : Exp PLUS error
    Stmt       : error SEMI

每个错误产生式调用统一的 reportSyntaxError 输出错误类型 B、行号和说明文字，并使用 yyerrok 清除 Bison 的错误状态，使分析器继续处理后续输入。

本次修正还增加了函数调用缺少右括号时的恢复规则：

    Exp : ID LP error

因此 exit(-1; 会报告 Miss ")"，而不会被错误地归类为普通语句错误。

yyerror 只负责记录语法错误，不再直接打印 Bison 的默认英文提示，从而避免默认提示和实验要求的自定义提示同时出现。当文件已经存在词法错误时，程序不再额外输出由非法字符引起的连锁语法提示。

### 4.5 构建兼容性处理

Flex 通常通过 libfl 提供 yywrap。为减少对外部库的依赖，main.c 中实现了：

    int yywrap(void) {
        return 1;
    }

因此 Makefile 中移除了不必要的 -lfl 链接选项。Linux 虚拟机中仍可使用指导书中的 make 命令完成构建。

## 七 遇到的问题与解决方法

### 7.1 Bison 默认错误提示不符合要求

原程序的 yyerror 会直接打印 syntax error, unexpected ...，与实验要求的错误类型和说明格式不一致。通过错误产生式调用 reportSyntaxError，并停止直接输出默认信息，解决了格式问题。

### 7.2 解析器错误恢复范围过大

原文法缺少 VarDec error 这种声明级同步规则，遇到错误后可能一直丢弃 token，导致后续错误无法报告。增加以分号等边界符恢复的规则后，可以继续解析后面的函数和语句。

### 7.3 嵌套注释不在当前实现范围内

Flex 的 COMMENT 状态只记录是否处于注释状态，不维护嵌套深度。因此 /* ... /* ... */ ... */ 不会被作为真正的嵌套块注释处理。该行为与当前 C-- 实验中普通块注释的要求一致，但如果需要支持嵌套注释，应增加注释深度计数器。

## 八 实验总结

本实验完成了一个面向 C--语言子集的词法分析器和语法分析器。通过 Flex 正则表达式可以识别关键字、标识符、整数、浮点数、运算符、分隔符和注释；通过 Bison 文法可以分析变量声明、结构体、函数、复合语句、循环、条件和表达式，并构造语法树。

实验中最重要的收获是理解了词法分析和语法分析之间的接口，以及错误恢复对编译器可用性的影响。仅让 Bison 检测到错误还不够，还需要选择合适的同步 token 并恢复分析状态，才能一次运行报告多个错误。最终测试表明，程序能够按要求输出错误类型、源程序行号和语法树信息。
